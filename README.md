# KICKVANA — Phase 1 MVP

Alternate-timeline football simulation: branch a (demo) match at any minute, change tactics/subs,
and see Monte Carlo win/draw/loss + xG with an opponent AI that reacts. **All teams, players and
match events are FICTIONAL demo data. Every alternate-timeline output is a hypothetical simulation.**

## Run
```bash
cd /workspace/touchline
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn backend.main:app --host 0.0.0.0 --port 8765   # UI at http://localhost:8765/
.venv/bin/python -m pytest -q                                   # tests
# screenshots: .venv/bin/pip install playwright && .venv/bin/python -m playwright install chromium && .venv/bin/python scripts_screens.py
```
API docs: http://localhost:8765/docs

## Layout
- `touchline_engine/` — independent simulation package (no web deps)
  - `models.py` Player/Team/Tactics/MatchState, formations & tactical options
  - `ratings.py` slot assignment (out-of-position penalty), unit ratings (attack/control/defence, fatigue-adjusted), tactical interaction model with human-readable reasons
  - `simulate.py` per-minute possession→shot→xG→goal model, vectorised Monte Carlo (numpy), Wilson 95% CIs, xG p10–p90, score distribution, game-state effects, fatigue drain, scheduled subs, `compare()` baseline-vs-alternate with common random numbers, `explain()` plain-English reasons
  - `opponent_ai.py` personalities (high-press, counter, possession, flexible, direct), difficulty (easy=1 reaction, normal=2, hard=all candidate reactions ranked by the rate model, more subs), fatigue-driven substitutions
  - `demo_data.py` fictional Northbridge Athletic vs Riverside Rovers + scripted "real" demo timeline (final 1–2)
  - `providers.py` provider-adapter interface; `DemoProvider` works; `APIFootballProvider`, `SportmonksProvider` are stubs that return "data unavailable" (HTTP 503) — never fabricated
- `backend/` FastAPI + SQLite (`db.py` schema is Postgres-portable)
- `frontend/index.html` dark single-page UI (pitch, tactics panel, real vs alternate, saved scenarios)
- `tests/` engine + API tests

## Features (Phase 1 + 'everything' pass)
- **Engine**: formations, pressing, line, width, tempo, build-up, focus, transition, **defensive approach** (zonal / man-oriented / compact), **set pieces** (attack: standard/near-post/aerial/short; defence: zonal/man/mixed, scaled by aerial ratings), **player roles** (target-man, false-nine, poacher, runner-in-behind, inverted-winger, ball-playing-defender, wing-back, box-to-box, anchor, playmaker; ignored if the player is in the wrong line), fatigue, subs, separate open-play and set-piece shot streams.
- **Opponent AI**: reacts at the branch point, then **re-reacts per Monte Carlo run** to the score: chasing/protecting variants per personality, with reaction delay after goals by difficulty (easy 10', normal 5', hard 2').
- **AI copilot** (`touchline_engine/copilot.py`): no LLM. It routes the question to topics, builds a diagnosis from the engine's rate model, generates candidate adjustments (tactics, roles, subs, formations), scores each by Monte Carlo expected points, and returns diagnosis / recommendation / benefits / risks / opponent response / alternatives. UI: *SIMULATE AI RECOMMENDATION* → Accept / Reject / Modify.
- **2D replay**: canvas replay of one sampled run (per-minute possession and ball frames plus shots/goals/subs/AI tactic switches), with play/pause, ±5', a scrub slider and a Real/Alternate toggle. Real mode uses only recorded demo events, with formation-based positions and no fabricated tracking data.
- **Accounts**: PBKDF2-SHA256 (240k iterations, salted) password hashes; opaque bearer tokens stored only as SHA-256; per-user scenarios; **Scenario Lab** comparing tactics and expected points.
- **Game modes**: fantasy club (pick an XI from the demo squad, which is used in sims), private leagues (join by code; standings = sum of challenge scores), **daily tactical challenge** (deterministic scenario per date; decision score 0–100 where 50 = no change and 100 = the copilot's best tested option), leaderboard, **post-match autopsy** (xG, key moments, model checkpoints).
- **Free vs Pro** enforced server-side (`backend/billing.py`): runs, saved scenarios, hard AI, copilot/day, leagues, autopsy checkpoints. **Stripe stub**: checkout returns a stub session without `STRIPE_SECRET_KEY`; the webhook verifies Stripe-format signatures (`STRIPE_WEBHOOK_SECRET`), is idempotent, and handles `checkout.session.completed` and `customer.subscription.deleted`. `POST /api/billing/dev-upgrade` works only when `TOUCHLINE_DEV_BILLING=1` (DEV ONLY).
- Screenshots: `screenshots/` (generated by `scripts_screens.py` with Playwright).

## Model & assumptions (be honest)
- Per minute, each team gets a shot with probability λ = base(0.21) × possession^0.6 × (attack/opp-defence)^1.6 × tactical multipliers; shot xG ~ Beta with mean = base 0.115 × quality multipliers; goal ~ Bernoulli(xG).
- Tactical multipliers are **hand-set heuristics** chosen to reflect common football reasoning (e.g. high line ↑ chance quality conceded, scaled by opponent-forward pace vs your defenders' pace; short build-up into a high press ↑ turnovers). They are NOT fitted to historical data. The model has **not been backtested** and must not be described as predictive/accurate.
- Fatigue: deterministic energy drain per minute by stamina × pressing/tempo multipliers; attributes scale 72–100% with energy. Subs restore a fresh player.
- Game-state: trailing teams push (more shots for and against) after ~60'.
- Opponent AI reacts once at the branch point (plus scheduled fatigue subs); per-run tactical re-reaction to goals is approximated by game-state effects.
- Same seed ⇒ identical results; ±~1–2 pts Monte Carlo noise across seeds at 5–20k runs.

## What's stubbed / next steps (roadmap)
- Remaining: LLM phrasing on top of the engine copilot (needs a key and must stay grounded); a true agent-level 2D sim (the replay is reconstructed from minute frames); live Stripe Checkout + customer portal; email verification, password reset, rate limiting and CSRF hardening for cookie use; player development/training, morale and chemistry; transfer market; real-time multiplayer.
- Phase 2: real provider mapping (API-Football/Sportmonks) + WebSocket live updates, dedupe, recovery; calibrate/fit tactical multipliers and base rates on licensed historical event data; backtest (Brier/log-loss vs bookmaker-free baselines); per-run in-sim opponent re-planning.
- Phase 3–5: competitive modes, leagues, monetisation, Postgres + Redis + workers for scale.
